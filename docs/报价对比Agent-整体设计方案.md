# 报价对比 Agent 整体设计方案

> v1.0，2026-09-08。本文是完整设计方案的单一入口，整合已定稿的全部决策。
> 配套文件：《quote_schema.json v1.1》（报价结构形式定义）、《原子工艺清单v2.xlsx》（453 条原子主数据）、《报价结构说明.md》（结构决策详解）。

---

## 1. 要解决的问题

向 N 家供应商询价后，各家报价单格式各异、工艺叫法各异、工艺路线各异，人工比价困难。本 Agent 解决：**投入 N 个报价单文件（Excel/Word/PDF/扫描件），自动解析为统一结构，直接呈现可比价的界面，人在查看比价时顺手修正问题。**

两条核心设计思想：
- **原子工艺映射**：所有供应商的加工费条目，统一映射到一部标准"原子工艺"词典（453 条，每条带多维标签），方言差异在映射层消化，对比层看到的是标准语言。
- **人不是流程的关卡，而是系统的增强器**：解析完直接进比价界面，不做前置人工确认；人的每次修正都回流主数据，系统越用越准。

## 2. 系统全貌

```
用户 → [前端·左侧菜单栏] 上传文件 → 进度页 → 比价界面(AI 分析/对比表/抽屉/就地编辑) → 报价对比历史 / 报价单数据 / 供应商管理 / 基础数据维护
                         │ REST + SSE
         [后端] 查重 → 接入 → 版面理解+品类判定 → 语义映射 → 校验 → 落库
                                    ↓                        ↓
                          机械对比引擎(纯脚本) ←—— JSON/关系库 ——┘
                                    ↓
                          LLM 综合分析层(AI 分析模块内容)
         [存储] SQLite(主数据+业务数据) + 对象存储(原件) + 文件系统(归档+JSON快照)
```

技术选型（可替换）：Python FastAPI + SQLite + 后台任务队列；前端 React SPA；进度用 SSE 推送。

## 3. 主数据

| 数据 | 内容 | 规模 |
|---|---|---|
| 品类 | 五金外壳/CMF/五金内置/塑胶/PCBA/硅胶/包材 | 7 |
| 原子工艺 | 编码（`AT-域码-序号`，永久稳定）、名称、别名集、三个维度标签、适用品类 | 453 |
| 三个独立维度 | 工艺域（34）、工艺阶段（12）、工艺类别（3）——**平行视角，无层级** | — |

## 4. 报价结构（Schema v1.1 要点）

每份报价单解析为一份标准 JSON，三个顶层块：**供应商信息 / 基本信息 / 报价信息**。

**全层级金额原则**：每个层级都有自己的金额字段，因为供应商可能只报模块价而没有明细。

```
最终含税单价（对比第一基准）
├─ 材料费 total → items[]（名称/金额/材质规格/自由说明）
├─ 生产加工费 total → items[]（★见 §5）
├─ 检验费 total → items[]
├─ 包装运输费 total → items[]（包装/运输）
├─ 损管利税 total → items[]（损耗/管理费/利润/税费，税率入 rate）
├─ 其他费用 total → items[]（说明必填，兜底用）
└─ 模治具费 total → 模具(名称/金额/穴数/寿命)/治具/钢网 各自 total → items[]
```

规则：
- 单价分解下所有金额为 **元/pcs**；模治具为 **元/项（一次性）**。
- 模块合计取值：**total > Σitems**；勾稽要求 **total ≥ Σitems**（合计可含未单列内容），小于则判异常。
- 汇总勾稽链：Σ模块合计（除税）= 未税合计 → +税额 = 含税合计 → −折扣 = 最终含税单价。允差 ±1%。
- 每条明细带**原文出处**（文件+位置+原文片段），全链路可回溯。

## 5. 生产加工费：统一结构与两个关键机制

加工费不做每品类独立结构——全品类条目形状一致，差异由原子映射表达。条目字段：名称(原文)/金额/原子编码/打包标志/候选原子/组合指纹/置信度/确认状态/出处。

**机制一：打包项指纹对齐**。供应商把多道工序打包报价（"CNC含去毛刺清洗 0.8元"）时，不强拆：记录候选原子列表，生成组合指纹；对比时把别家分开报的相同工序聚成同指纹再比，两种报价形态在同一基准上，数字完全忠实原始报价。

**机制二：新工艺上报**。清单外工艺 `atom_code` 留空并置 `is_new_process=true`，金额照常参与合计；前端弹出决策卡片，用户一键【新增原子】（自动分配编码、收录别名）或【归并现有】（原文回流别名表）。

## 6. 端到端流水线（一次对比的完整过程）

```
⓪ 查重(脚本)      文件哈希比对，已解析过直接复用历史结果（可强制重跑）
① 接入(脚本)      Excel/Word/PDF/扫描件 → 统一中间表示 IR + 原件归档
② 版面理解(LLM)   从 IR 直接产出结构化字段值（含金额）+ 品类自动判定
                  脚本独立交叉验证：一致→高置信；不一致→双值保留打标，人裁定
③ 语义映射        非加工费：同义词表规则映射，归不进的进"其他费用"
                  加工费三级流水：
                    L1 别名精确匹配(脚本) → high
                    L2 LLM 从该品类候选原子集(约150条)里选编码 → 可识别打包项/新工艺
                    L3 无法判断 → atom_code=null, low
                  ★ 任何级别金额都保留，匹配失败只损失对比粒度
④ 校验(脚本)      Schema/枚举/勾稽/交叉验证异常——全部只打标不阻断
⑤ 落库(脚本)      JSON 快照存档 + 拍平写入关系表（含各模块合计列 + other_info 其它信息）
⑥ 机械对比(脚本)  层级金额对比表 + 加工费维度抽屉汇总 + 指纹对齐 + 模治具对比
⑦ 综合分析(LLM)   读取⑥的结构化结果（+ 各家解析阶段的「其它信息」），生成 AI 分析模块内容（见 §7）
⑧ 人的环节        比价界面上：看 AI 分析 → 查异常徽标 → 就地修正 → 新工艺决策
⑨ 沉淀(自动)      别名回流、新原子入库、任务存档——下次命中率更高
```

**品类判定**在②段由 LLM 完成（依据零件名/材料/工艺用词），低置信打标，用户在比价界面可改，改后自动重跑该单的原子映射。

## 7. 比价界面：用户看到的一切

用户看到的第一个结果界面就是比价界面，自上而下：

1. **AI 分析模块**（最顶部，位于「报价对比」之上；AI 生成）：按供应商成列的对比表——含税单价（带 `最低`/`最高` 标签）、优势、劣势、风险、建议；其中优势/劣势/风险各自可展开 3 个固定子维度，展开方式与「报价对比」模块一致（`+`/`−` 号 + 同款底色区分）。表格允许横向拖动，供应商多时不挤压。
   - 子维度：优势（成本/材料、工艺/质量、商务/交付）；劣势（成本/费用、材料/工艺、商务/交付）；风险（质量/合规风险、成本/商务风险、资金/交付风险）。
   - 输入是**已解析的结构化数据**（各家头信息+模块合计+明细+抽屉汇总+模治具+警示项+`other_info` 其它信息），**源文件不交给 LLM**。
   - 触发时机：文件解析完毕首次进入比价页自动触发；页面刷新不触发；新增供应商后再进比价页重新触发；同时提供手动「重新分析」按钮。
   - 推理过程中展示占位模块（动画 + 阶段文案 + 已耗时），完成后自动替换为表格。
   - 硬规矩：**输出中的每个金额由脚本与机械对比结果对账**，对不上标「部分数字待核对」。
2. **层级金额对比表**：N 家供应商横向对比，从最终含税单价到六模块合计，每行 **+/− 号折叠展开**子项。
3. **加工费专区**：抽屉切换器（工艺域/工艺阶段/工艺类别/自定义抽屉）；空值显示"路线未含此工序"，**绝不显示为 0**；打包项标"含打包"。
4. **警示徽标**：勾稽异常 / 交叉验证异常 / 低置信度 / 未匹配 / 新工艺候选 / 品类存疑——点击即过滤定位，就地修正。
5. **模治具对比区**：费用/穴数/寿命横向排列。

## 8. LLM 与脚本的分工原则

- **脚本负责**：格式解析、查重、别名精确匹配、校验、对比聚合、落库——确定性的事必须 100% 可靠可复现。
- **LLM 负责**：版面理解与字段产出、品类判定、别名未命中时的原子匹配（**只能从候选集选编码，不允许生成编码**）、新工艺判定、综合分析（AI 分析模块内容）。
- **交叉验证**而非互斥：LLM 产出的金额由脚本独立复核，不一致双值保留给人看。
- **边界实测可调**：以上分工是初始假设，每段的取舍以评估集（`eval_replay`，10-20 份历史报价单标注标准答案）实测命中率为调整依据，不由设计文档锁死。

## 9. 数据存储

- **JSON 是处理基准**：解析、校验、确认、对比过程中的所有操作在 JSON 上进行；确认后的 JSON 快照原样存档（审计、重解析、结构迁移用）。
- **关系库是查询索引**：跨报价单聚合对比天然是 SQL 场景；`quote` 表冗余六个模块合计列，层级对比查询免聚合；`quote.other_info` 保存解析阶段额外识别到的其它信息（markdown，已剔除手机号/姓名/邮箱/印章等个人信息与银行开户信息），供 AI 分析模块作为补充信息源。
- **对象存储存原件**：报价单上传即入对象存储（`stored_object` 表记元数据 + 后端 `app/storage.py` 二进制存储），解析结果保留 `source_file_name`，前端可在线预览（PDF/图片）或下载原件。本地实现为内容寻址：key = `objects/<sha256 前两位>/<sha256><扩展名>`，同一份文件重复上传只占一份空间（硬链接去重），上传失败只打 `parse_log` 的 `store_failed` 告警，不阻断解析。接口抽象为 `ObjectStore`，`S3ObjectStore` 预留，配置项 `OBJECT_STORE_BACKEND=local|s3`、`OBJECT_STORE_DIR`。
- SQLite 起步（单机零运维，备份=复制文件），多人协作时平迁 PostgreSQL，表结构不变。

## 12. 关键不变量（任何迭代不得破坏）

1. **金额永不受损**：匹配失败只损失对比粒度，金额永远落库、永远可见。
2. **层级金额可信**：total ≥ Σitems 规则固定，勾稽失败打标不隐藏。
3. **LLM 数字回检**：AI 分析模块输出中的所有金额必须与机械对比对账。
4. **证据链完整**：每条数据可回溯到原文件原文位置。
5. **空值语义**："没报"显示为"路线未含此工序"，绝不当 0 元。
6. **主数据变更留痕**：原子新增/别名回流/抽屉变更都有来源与时间戳。
